# Запуск всех лабораторных — по порядку, с нуля

Команды в блоках `powershell` выполняются **на своём компьютере (Windows)** в папке
репозитория, команды в блоках `bash` — **внутри рабочей Linux-ВМ** `docker`
(там уже есть Docker, make, git и Python, ничего ставить в Windows не нужно).

Адреса ВМ (внутренняя сеть VirtualBox `172.27.206.0/24`, доступна с компьютера):

| ВМ | Адрес | Зачем | Открыть в браузере |
|---|---|---|---|
| `db` | 172.27.206.20 | ЛР2: PostgreSQL | — |
| `app` | 172.27.206.10 | ЛР2: приложение без контейнеров | http://localhost:8000 |
| `docker` | 172.27.206.30 | рабочая ВМ: ЛР1, ЛР3–ЛР7 | http://localhost:8080 (контейнеры ЛР4) |
| `staging` | 172.27.206.40 | ЛР6: тестовое окружение CD | http://localhost:8180 |
| `infra-stage` | 172.27.206.60 | ЛР7: окружение staging (Ansible) | http://localhost:8280 |
| `infra-prod` | 172.27.206.70 | ЛР7: окружение production (Ansible) | http://localhost:8380 |

## 0. Один раз: установка и подготовка

1. Установить: **Git for Windows**, **VirtualBox 7**, **Vagrant 2.4**
   (в BIOS должна быть включена виртуализация). Docker Desktop не обязателен.
2. Скачать репозиторий и положить пароль vault (ЛР7, у команды; в Git его нет):
```powershell
git clone https://github.com/DaniilKrivencev/DevOps2026.git
cd DevOps2026
Set-Content -NoNewline infra\ansible\.vault_pass "<пароль vault>"
```
3. Поднять рабочую ВМ и зайти в неё (первый раз ~5–10 минут):
```powershell
vagrant up docker
vagrant ssh docker
```
4. Внутри ВМ — своя копия репозитория (в общей папке Windows не работают права
   и символические ссылки, которые нужны venv и ssh):
```bash
git clone https://github.com/DaniilKrivencev/DevOps2026.git ~/DevOps2026
cd ~/DevOps2026
cp /opt/cityduma-src/infra/ansible/.vault_pass infra/ansible/      # пароль vault (ЛР7)
```
Дальше все `bash`-команды — из `~/DevOps2026` в ВМ `docker`
(зайти снова: `vagrant ssh docker`, затем `cd ~/DevOps2026`).


На сервере приложения:
```bash

sudo iptables -L INPUT -n -v                   # firewall
```
Остальные проверки защиты (перезагрузка, остановка БД, порт БД снаружи) — раздел 5 отчёта ЛР2.

## ЛР6. Continuous Delivery  ·  [отчёт](labs/lab6/README.md)

Один раз — ключ pipeline и тестовое окружение (на компьютере, в папке репозитория;
в Git Bash, а не PowerShell):
```bash
ssh-keygen -t ed25519 -N "" -C cd-deploy -f deploy/cd_deploy_key
vagrant up staging
```
Образ должен читаться без входа: GitHub → **Packages → devops2026 → Package settings →
Change visibility → Public** (или настройка registry из раздела 4 отчёта ЛР6).

В ВМ `docker`:
```bash
install -m 600 /opt/cityduma-src/deploy/cd_deploy_key ~/.ssh/cd_deploy_key
ssh-keyscan -H 172.27.206.40 >> ~/.ssh/known_hosts     # доверять ключу сервера staging (один раз)
export STAGING_HOST=172.27.206.40 STAGING_SSH_KEY=~/.ssh/cd_deploy_key
make cd-deploy TAG=0.7.2   # pull из registry → запуск → проверка релиза: http://localhost:8180
make cd-status             # что работает + история выпусков
make cd-deploy TAG=0.6.2   # выпуск другой версии
make cd-rollback           # возврат предыдущей
make cd-deploy TAG=sha-0000000bad     # неверный тег — работающая версия не трогается
```

## ЛР7. Управление конфигурацией (Ansible)  ·  [отчёт](labs/lab7/README.md)

На компьютере — две чистые ВМ:
```powershell
vagrant up infra-stage infra-prod
```
В ВМ `docker` (ключи Vagrant нужны Ansible для первого входа на чистые машины):
```bash
cp -r /opt/cityduma-src/.vagrant .
make infra-lint                      # yamllint, ansible-lint, синтаксис, требования к коду
make infra-check ENV=staging         # что будет изменено, без применения
make infra-apply ENV=staging         # подготовка чистой машины → http://localhost:8280
make infra-apply ENV=staging         # повторно: в PLAY RECAP changed=0
make infra-apply ENV=production      # второе окружение → http://localhost:8380
make infra-verify ENV=staging        # только проверка
make infra-test                      # чистая машина → changed=0 → ручные правки → восстановление
```

## Выключить / удалить ВМ

```powershell
vagrant status                       # что запущено
vagrant halt                         # выключить все (данные сохраняются)
vagrant destroy -f staging infra-stage infra-prod   # удалить ненужные
```

## Если что-то не так

| Симптом | Что сделать |
|---|---|
| `vagrant up` ругается на виртуализацию | включить VT-x/AMD-V в BIOS, выключить Hyper-V: `bcdedit /set hypervisorlaunchtype off` и перезагрузка |
| порт занят (`8000`, `8080` …) | `vagrant halt` лишних ВМ или остановить программу, которая держит порт |
| `make: command not found` | команда выполняется не в ВМ `docker`: `vagrant ssh docker`, `cd ~/DevOps2026` |
| `permission denied` у Docker в ВМ | выйти и зайти снова (`exit`, `vagrant ssh docker`) — группа docker применяется при новом входе |
| ЛР6/ЛР7: не скачивается образ из ghcr.io | сделать пакет публичным (см. ЛР6) |
| ЛР7: `Decryption failed` | неверный или отсутствует `infra/ansible/.vault_pass` |
