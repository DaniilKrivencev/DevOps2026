# История версий

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).

## [0.7.3] — инструкция запуска

### Добавлено
- `ЗАПУСК.md`: команды запуска всех лабораторных по порядку, начиная с установки.

## [0.7.2] — исправления после переписывания истории и стенда «чистой машины»

### Исправлено
- `.gitleaksignore`: обоснованные исключения перенесены на новые хеши коммитов.
- Этап guard: если прежней вершины ветки нет (история переписана), сравнение пропускается
  с предупреждением, а не падает.
- `make infra-test`: Docker 29 внутри стенда хранит слои в `/var/lib/containerd` —
  каталог вынесен в отдельный том (overlay поверх overlay не распаковывает whiteout-файлы).

## [0.7.1] — исправление ЛР7

### Исправлено
- Роль docker на чистой машине: модулю `deb822_repository` нужен пакет `python3-debian`
  (добавлен в базовые пакеты), каталог `/etc/apt/keyrings` создаётся явно.
  Ошибку обнаружил этап «Чистая машина» pipeline инфраструктуры.

## [0.7.0] — ЛР7: управление конфигурацией и воспроизводимая инфраструктура

### Добавлено
- `infra/ansible`: роли base, users, ssh, firewall, docker, app, verify; окружения staging,
  production и ci; параметры общие / окружения / узловые / секретные (ansible-vault).
- Управляющий узел Ansible в контейнере (`scripts/infra.sh`), команды `make infra-*`.
- `make infra-test`: чистая машина → повторный запуск без изменений → ручные изменения →
  восстановление; проверка доступности приложения после настройки.
- Pipeline `.github/workflows/infra.yml`, требования к инфраструктурному коду
  (`scripts/infra_policy.py`), CODEOWNERS для ролей, окружений и секретов.
- Чистые ВМ `infra-stage` и `infra-prod` в Vagrantfile.

## [0.6.2] — инструкции по лабораторным

### Добавлено
- В каждом `labs/labN/README.md`: «Как запустить и показать» в начале и «Ответы на основные вопросы» в конце.
- `labs/README.md`: раздел «С чего начать» — что установить и где запускать.

## [0.6.1] — порядок в репозитории

### Изменено
- Материалы каждой лабораторной — в своём каталоге `labs/lab1` … `labs/lab6`
  (отчёт `README.md`, файлы проекта, команды проверки); навигация — `labs/README.md`.

## [0.6.0] — ЛР6: Continuous Delivery

### Добавлено
- `GET /version`: версия, коммит и время сборки работающего образа.
- Тестовое окружение staging (ВМ `staging`, `deploy/staging/`), отдельная учётная запись
  pipeline `cd-deploy` с принудительной командой.
- Pipeline доставки `.github/workflows/cd.yml`: после успешного CI для `main` и тегов,
  ручной выпуск конкретного тега и возврат предыдущей версии.
- Проверка релиза после развёртывания: контейнеры, `/health`, `/version`, основной
  пользовательский сценарий (`scripts/smoke_test.py`); автоматический возврат при неудаче.
- Защита от одновременных развёртываний (concurrency + flock), `make cd-*`.

### Процесс
- Конфликты слияния разрешаются в отдельной ветке `conflict/<ветка>` (CONTRIBUTING.md).

## [0.5.0] — ЛР4, ЛР5 и доработки ЛР1–ЛР3

### Добавлено
- Авторизация HTTP Basic с ролями `admin` / `secretary` (ЛР1).
- Журналирование запросов и ошибок, request id, формат text/json (ЛР1).
- Развёртывание на двух ВМ: iptables, SSH только по ключам, администратор `duma-admin`,
  роли БД `duma_owner` / `duma_app`, пароли вне репозитория (ЛР2).
- Контейнеризация: Dockerfile, Compose (db, migrate, 2 экземпляра приложения, nginx),
  `make container-check` (ЛР4).
- CI в GitHub Actions: этапы в Docker-in-Docker, тестовая БД, кэш, тег по SHA,
  блокировка публикации, CODEOWNERS и этап guard (ЛР5).
- `requirements.lock`, `make audit`, `make ci`.

### Изменено
- Единая кодовая база в корне репозитория (бывший каталог `lab3/`).
- Зависимости обновлены: fastapi 0.163.2 (starlette 1.10.0), jinja2 3.1.6, python-dotenv 1.2.4.

### Безопасность
- Из репозитория удалены локальные ключи Vagrant (`.vagrant/`) и пароли из скриптов развёртывания.
